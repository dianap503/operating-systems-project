# Database Format Specification (FORMAT_DB)

This document describes the structure of the binary databases generated by `fileops_indexer` (`index.db`) and `proc_snapshot` (`proc.db`) as required for assignment T3.

---

## 1. File Structure Overview
Both databases follow a consistent binary layout consisting of:
1. **The Header** — A fixed-size block containing global metadata about the snapshot.
2. **The Record Area** — A sequence of records corresponding to files or processes, managed under strict synchronization.

---

## 2. Header Structure
The header is placed at the very beginning of the binary file and has a fixed size. It contains the following fields:

| Field Name | Type | Size (Bytes) | Description |
| :--- | :--- | :--- | :--- |
| `magic` | `char[4]` | 4 | Fixed identifier (`IDX1` for index.db, `PRC1` for proc.db) |
| `format_version` | `uint32_t` | 4 | Version number of the binary format |
| `snapshot_id` | `uint64_t` | 8 | Unique identifier of the snapshot (timestamp-based) |
| `snapshot_state` | `int32_t` | 4 | State of the snapshot: `0` for OPEN, `1` for SEALED |
| `active_writers` | `int32_t` | 4 | Number of concurrent instances currently contributing |
| `record_count` | `uint32_t` | 4 | Total number of valid records stored in the database |

---

## 3. Record Structure (`index.db`)
For each indexed file or directory, the record contains:
* **`file_type`** (`int32_t`): The type of the file (regular file, directory, symlink, fifo, etc.).
* **`path_len`** (`uint64_t`): The length of the absolute path string.
* **`abs_path`** (`char[]`): The absolute path of the file (relative to `/`).
* **`size`** (`int64_t`): File size in bytes (stored for regular files; `0` for other types).
* **`hash`** (`unsigned long`): DJB2 checksum/hash of the file contents (`0` for non-regular files).
* **`mtime`** (`int64_t`): Last modification timestamp.
* **`st_dev`** (`uint64_t`): Device ID from the `stat` structure (part of the binary file name/identifier).
* **`st_ino`** (`uint64_t`): Inode number from the `stat` structure.

---

## 4. Limits and Constraints
* **Maximum Path Length**: Bounded by `PATH_MAX` (typically 4096 bytes).
* **Key Uniqueness**: No duplicate records with the same absolute path are allowed within the same snapshot. Symlinks are recorded as symlinks without recursive traversal.

---

## 5. Concurrency and Update Strategy
* **Synchronization**: Handled directly on the database file using exclusive locks via `fcntl(2)`.
* **Writers Management**: The first instance creates the file, initializes the header (`OPEN`, `active_writers = 1`). Subsequent instances attach by incrementing `active_writers` under an exclusive header lock.
* **Sealing**: When an instance finishes, it decrements `active_writers`. The instance that brings the count to `0` automatically marks `snapshot_state = SEALED`.
